# Если изменился формат событий

Чтобы бот продолжил опрос после повреждённого ответа `/updates`, включите режим `skip` при создании клиента:

```python
import os
from itd_bot import Bot, Dispatcher

with Bot(os.environ["ITD_TOKEN"], on_protocol_error="skip") as bot:
    router = Dispatcher.from_bot(bot)
    router.run_polling(state_path=".bot-state.json")
```

По умолчанию действует `on_protocol_error="raise"`: неожиданная форма вызывает `ProtocolError`. Режим `skip` влияет только на `/updates`; ошибки HTTP, сети, обработчиков и других методов обрабатываются по прежним правилам.

- Если оболочка пакета корректна, SDK пропускает элементы без строкового `type`, передаёт остальные события и сохраняет серверный курсор пакета.
- Если оболочка повреждена, курсор отсутствует, некорректен или движется назад, SDK возвращает пустой пакет с прежним курсором. Опрос ждёт `interval` и повторяет чтение. HTML или другой не-JSON ответ сохраняется как `bytes`.
- Неизвестные имена событий, типы чатов и дополнительные поля сохраняются без изменений.
- `reset_required=true` всегда вызывает `ResetRequired`, даже если остальные поля повреждены. Сверьте состояние приложения перед продолжением.

> **Осторожно.** Пропущенный элемент не попадёт в обработчик. При сохранении курсора исправного пакета он может больше не прийти. Если весь ответ остаётся повреждённым, бот продолжит опрос с прежнего курсора, но обработка новых событий остановится до восстановления формата.

## Проблемные фрагменты

`bot.protocol_errors` возвращает копии последних 32 пропущенных фрагментов, от старого к новому. Буфер общий для потоков одного `Bot`, ограничен числом записей и очищается при завершении процесса. Файлы автоматически не создаются. В лог попадает только предупреждение о пропуске, без данных ответа.

Во фрагментах могут оказаться личные сообщения, курсоры и другие закрытые данные. Не выводите буфер целиком в логи и не прикладывайте его к Issue без очистки. Для диагностики достаточно начать с `len(bot.protocol_errors)`.

## Неизвестные значения

При необходимости преобразуйте сырые значения в перечисления самостоятельно:

```python
from itd_bot import ChatType, EntityType

assert ChatType.DIRECT == 0
assert EntityType.BOLD == "bold"

chat_type = ChatType(73)  # Вымышленный неизвестный тип.
assert chat_type.name == "UNKNOWN"
assert chat_type.value == 73
assert chat_type == 73

entity_type = EntityType("future_entity")
assert entity_type.name == "UNKNOWN"
assert entity_type == "future_entity"
```

В `ChatType` подтверждён только `DIRECT=0`; остальные целые значения принимаются без предположений о смысле. В `EntityType` перечислены текстовые стили, уже поддержанные `Text`: `bold`, `italic`, `underline`, `strike`, `code`, `spoiler`, `text_link`. Это не полный каталог сервера.

`UNKNOWN=-1` у `ChatType` и `UNKNOWN="unknown"` у `EntityType` — локальные обозначения SDK. Для неизвестного значения проверяйте `.name == "UNKNOWN"`, а не равенство с этим обозначением: исходное значение сохраняется. Неизвестные значения не добавляются в глобальный кэш перечисления. Ответы API автоматически не преобразуются.

Разбор и продолжение опроса проверены на `httpx.MockTransport`, без живых запросов к ИТД. Перечисления не включают скрытые возможности сайта.
