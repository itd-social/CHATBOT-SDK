# Диалоги с состоянием

Сохраните шаг диалога и верните управление: следующий ответ придёт в новый вызов обработчика. Не ждите ввода пользователя внутри потока.

```python
from itd_bot import FSM, Bot, MemoryFSMStore, Router, filters

fsm = FSM(MemoryFSMStore(), namespace="name-bot")
dialogue = Router()

@dialogue.message(filters.command("start"))
def start(ctx):
    ctx.reply("Как вас зовут?")
    fsm.set(ctx, "name")

@dialogue.message(filters.state(fsm, "name"), lambda ctx: bool(ctx.text))
def name(ctx):
    ctx.reply("Спасибо за ответ!")
    fsm.clear(ctx)

with Bot.from_env() as bot:
    router = Router.from_bot(bot, **bot.dispatcher_options)
    router.include_router(dialogue)
    polling = {**bot.poll_options, "chat_queues": True}
    router.run_polling(state_path=".bot-state.json", **polling)
```

Настройте [окружение](ENVIRONMENT.md) перед запуском. Полная анкета из трёх шагов — имя, возраст, подтверждение — находится в [`examples/fsm_bot`](../examples/fsm_bot/README.md); `/cancel` очищает её состояние.

## Сохраните состояние и данные

```python
record = fsm.get(ctx)  # {"state": None, "data": {}} до первого перехода
fsm.set(ctx, "age", data={"name": ctx.text})
record = fsm.get(ctx)  # отдельная копия состояния и вложенных данных
fsm.set(ctx, "confirm", data={**record["data"], "age": "21"})
fsm.clear(ctx)  # удалить и состояние, и данные
```

Ключ состоит из `(namespace, chat_id, sender_id)`. Передайте отдельный непустой `namespace` каждому боту или аккаунту, который использует общее хранилище. В разных чатах и у разных отправителей состояния независимы. `get` возвращает обычный словарь с подсказкой `FSMRecord`, исходный контекст не изменяется.

`set` целиком заменяет запись: без `data` сохраняется пустой словарь. Состояние может быть строкой или `None`; `clear` удаляет запись. Изменение результата `get` ничего не сохраняет — передайте новые данные через `set`. Методы FSM принимают `MessageContext`, включая `CommandContext`.

`filters.state(fsm, None)` выбирает сообщения без активного состояния, `filters.state(fsm, "age")` — нужный шаг. Их можно соединять с другими фильтрами через `&`, `|`, `~`. Для остальных событий фильтр возвращает `False`.

## Выберите хранилище

| Хранилище | Когда использовать |
|---|---|
| `MemoryFSMStore()` | Один процесс; всё теряется при перезапуске |
| `FileFSMStore(".fsm-state.json")` | Небольшой бот с сохранением между запусками |
| `RedisFSMStore(client)` | Уже есть синхронный потокобезопасный клиент Redis |
| `RedisFSMStore.from_url(url, **kwargs)` | Создать клиент Redis через optional extra |

Память и файл защищают отдельные операции блокировками. Делите один `FileFSMStore` между потоками, работающими с одним файлом. Разные экземпляры и процессы не координируют его перезапись. Родительская папка должна существовать. Запись идёт через временный файл и атомарную замену; при ошибке старый файл сохраняется. Повреждённый или неизвестный формат вызывает ошибку и не сбрасывается автоматически.

Данные файла и Redis должны поддерживать JSON; используйте строки, числа, списки, словари со строковыми ключами, `bool` и `None`. Память копирует данные через `deepcopy`. Очищайте завершённые диалоги: автоматического срока хранения нет.

Файл содержит данные пользователей. Стандартные `.fsm-state.json` и его временные файлы исключены из Git и дистрибутива; для другого имени настройте свои исключения и доступ к файлу.

### Redis

```sh
python -m pip install "itd-chatbot-sdk[redis]"
```

```python
import os
from itd_bot import FSM, RedisFSMStore

with RedisFSMStore.from_url(
    os.environ["REDIS_URL"], socket_connect_timeout=5, socket_timeout=5,
) as store:
    fsm = FSM(store, namespace="questionnaire-bot")
    # Запустите здесь Router и завершите polling до выхода из with.
```

Переданный клиент остаётся вашим; созданный через `from_url` закрывается методом `close()` или через `with`. По умолчанию `from_url` отключает повторы клиента Redis. Явные параметры подключения передаются библиотеке; выберите сервер, поддерживаемый вашей версией [redis-py](https://github.com/redis/redis-py#supported-redis-versions).

Одна запись сохраняется командой `SET`, чтение и удаление используют `GET` и `DEL`. Redis атомарно заменяет запись целиком, но не объединяет несколько вызовов FSM в транзакцию. Префикс ключей по умолчанию — `itd:fsm`; сырой ключ диалога заменён SHA-256. Данные внутри значения остаются читаемым JSON.

## Порядок, ошибки и повторы

Включите [очереди по чатам](CHAT_QUEUES.md): `chat_queues=True` сохраняет порядок обработки одного чата между пакетами и позволяет читать новые пакеты, пока работают обработчики. Разные чаты продолжают работать параллельно.

В одном `run_polling` обычный режим `chat_queues=False` тоже сохраняет порядок чата: события группируются по чату, затем цикл ждёт весь пакет. Его ограничение — долгий обработчик задерживает чтение следующего пакета и новые сообщения остальных чатов. Прямые одновременные вызовы `handle()` и несколько циклов polling между собой не сериализуются.

Блокировка `get` и `set` не защищает всю последовательность «прочитать — изменить — сохранить». Между процессами очереди SDK не координируются; для одного диалога нужен один обработчик-владелец. Это относится и к общему Redis.

Оставьте `match="first"`, как в примере. В режиме `all` следующий фильтр увидит уже изменённое состояние и может обработать то же сообщение на новом шаге; верните `Router.STOP`, чтобы остановить цепочку.

Ошибки хранилища доходят до [политики `on_error`](USAGE.md#если-обработчик-упал). По умолчанию ошибка обработчика пропускается; в примере анкеты установлен `ErrorAction.STOP`, чтобы не продвигать курсор после ошибки. Исправьте причину перед повторным запуском.

Запись состояния и ответ ИТД — отдельные операции. Сбой после одной из них оставляет частично выполненный шаг; `RETRY` может повторить ответ или переход. FSM не даёт гарантии однократной доставки и не добавляет повторов HTTP-записей.

Для своего хранилища реализуйте `FSMStore`: потокобезопасные `get(key)`, `set(key, state, *, data=None)` и `clear(key)`. Возвращайте отдельную копию `FSMRecord`, а для отсутствующего ключа — `{"state": None, "data": {}}`. При ошибке не сообщайте об успешной записи.
