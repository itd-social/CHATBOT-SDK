# Первый бот

Создайте готового бота с `/start` и `/ping` одной командой. Нужны Python 3.10+, аккаунт бота и его `refresh_token`. Для отправки сообщений аккаунту нужна подписка **«ИТД НУКСТА»**.

## 1. Создайте проект

Установите или обновите SDK, затем запустите генератор:

```sh
python -m pip install --upgrade itd-chatbot-sdk
python -m itd_bot init my-bot
```

Команда создаст новую папку `my-bot`, отдельное окружение `.venv` и установит туда SDK с дополнением `[env]`. Системное окружение не меняется. Для скачивания зависимостей нужен интернет.

В папке появятся короткий `bot.py`, `.env`, `.env.example`, `.gitignore`, `requirements.txt` и README. Тестов, CI и дополнительных команд в проекте нет. Хотите другой путь, например с пробелами? Укажите его в кавычках:

```sh
python -m itd_bot init "my projects/my-bot"
```

## 2. Впишите токен

Возьмите cookie `refresh_token` по [инструкции](AUTH.md#как-получить-refresh_token). Откройте созданный `my-bot/.env` и добавьте значение:

```dotenv
ITD_REFRESH_TOKEN=ЗНАЧЕНИЕ_COOKIE
```

Вставляйте только значение, без `refresh_token=` и пробелов. `.env` явно загружается через `python-dotenv`; уже заданные переменные окружения имеют приоритет.

## 3. Запустите бота

Генератор напечатает точную команду запуска с полными путями. Выполните её: активировать `.venv` или переходить в папку проекта не требуется.

Если вы уже в папке `my-bot`, можно запустить так.

Linux/macOS:

```sh
.venv/bin/python bot.py
```

Windows PowerShell:

```powershell
& .\.venv\Scripts\python.exe bot.py
```

Напишите аккаунту бота `/start`, затем `/ping`: бот ответит приветствием и `pong`. Чтобы добавить свою команду, скопируйте обработчик в `bot.py` и поменяйте имя и ответ. Остановка — `Ctrl+C`.

Сессия `.itd-session.json` и курсор `.bot-state.json` сохраняются рядом с `bot.py`, даже при запуске из другой папки. При первом запуске старые сообщения пропускаются. Секреты, курсор и `.venv` уже исключены из Git.

## Если проект не создался

| Что произошло | Что сделать |
|---|---|
| Путь уже существует | Выберите новое имя, даже если существующая папка пустая. Генератор её не меняет |
| Не удалось создать файлы | Проверьте путь, права доступа и свободное место |
| Не удалось создать `.venv` | Установите поддержку `venv` и `ensurepip` для своего Python; в Ubuntu/Debian — пакет `python3-venv`. Файлы сохранятся, для нового запуска генератора выберите другую папку |
| Зависимости не скачались | Проверьте интернет и доступ к PyPI, затем повторите напечатанную команду установки. Файлы проекта и `.venv` сохранятся |
| Создание прервано через `Ctrl+C` | Частично созданная папка сохраняется; для нового запуска генератора выберите другую |

После повторной установки зависимостей команда запуска из папки проекта указана [выше](#3-запустите-бота) и в созданном README.

## Перед запуском на сервере

Несколько вещей, которые лучше знать заранее:

- **Одна сессия, один бот.** Не запускайте две копии на одной refresh-сессии и не открывайте её параллельно в браузере: процессы друг о друге не знают, и сессия может сломаться.
- **События могут прийти дважды.** Если бот упал после ответа, но до сохранения курсора, событие обработается повторно. Старайтесь, чтобы обработчики это переживали.
- **`ResetRequired`.** Так сервер сообщает, что не может отдать все пропущенные события. Остановитесь и сверьте состояние с чатами: SDK ничего не пропустит за вас.
- **Файл сессии.** `.itd-session.json` хранит токен в открытом виде. Не публикуйте его и закройте доступ к папке.
- **Если сессия истекла**, боту нужна новая cookie. Бесконечные повторы не помогут.

Хочется быстрее или тяжелее? В [руководстве](USAGE.md#быстрые-обновления-и-параллельная-работа) рассказано про WebSocket и `workers`.
