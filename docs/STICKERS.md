# Стикеры: статус

SDK умеет прочитать сущности `sticker` из входящего JSON и выбрать их фильтром Router. Отправки, каталога, паков и получения изображений стикеров нет; активация функции на сайте не подтверждена.

```python
from itd_bot import MessagePayload, message_stickers

sample: MessagePayload = {
    "entities": [{"type": "sticker", "sticker_id": "EXAMPLE_STICKER_ID"}],
}
for entity in message_stickers(sample):
    sticker_id = entity.get("sticker_id")
```

Это подставной JSON. Работающий автономный пример: [`examples/sticker_reading.py`](../examples/sticker_reading.py).

## Выберите входящее сообщение

```python
from itd_bot import MessageContext, filters, message_stickers


@router.message(filters.sticker() & filters.chat("CHAT_ID"))
def incoming(ctx: MessageContext) -> None:
    entities = message_stickers(ctx.message)
    # Здесь доступны исходные словари, включая неизвестные поля.
```

Создайте `router` по [руководству Router](ROUTER.md). Фильтр совпадает, если среди `entities` есть словарь с `type="sticker"`; для других событий возвращает `False`. Он не обращается к серверу и не проверяет ID.

Хелпер возвращает новый список со ссылками на исходные словари в прежнем порядке. Отсутствующий или некорректный список `entities` даёт `[]`; элементы других типов пропускаются. Хелпер не меняет входные данные. Если измените возвращённый словарь, изменится и исходная сущность.

## Типы и неполные данные

`EntityType.STICKER` сравнивается со строкой `"sticker"`. Неизвестные значения перечисления по-прежнему сохраняют исходную строку.

`StickerEntity` описывает только подтверждённые поля `type: str` и `sticker_id: str`. В валидаторе клиента `sticker_id` обязателен, должен быть строкой длиной до 64 единиц UTF-16. Для этой ветки нет проверки на непустую строку; `offset` и `length` ей не требуются.

Как и остальные представления сырого JSON, `StickerEntity` использует `total=False`: подсказки не обещают наличия ключа и не проверяют входящие данные. Сущности без ID, с неожиданным ID или дополнительными полями доходят до обработчика целиком. Перед использованием значения проверяйте его тип. Это не спецификация сервера.

## Отправка

При `validate_limits=True` сущность `sticker` в отправке или правке вызывает `MessageValidationError(ValueError)` до HTTP-запроса, со ссылкой на [#17](https://github.com/itd-social/CHATBOT-SDK/issues/17). Подробности опции — в [лимитах сообщения](USAGE.md#лимиты-текста-и-вложений).

По умолчанию SDK сохраняет прежнюю передачу сырых `entities`; это не подтверждение, что сервер принимает стикеры. Не используйте этот путь как поддержку отправки стикеров.

## Что проверено

В локальном `index-1f7c8b01465d.js` проверены ветка `nA` для сущности и запрет отправки `jd`. Рабочая отрисовка стикеров этой проверкой не подтверждена. Приём целого сообщения и сохранение неизвестных полей проверены через `httpx.MockTransport` и подставной WebSocket; живой стикер ИТД не проверялся.

Полноценная поддержка требует отдельной задачи после появления подтверждённых вызовов в бандле и живой проверки формата. [Опись API](API_COVERAGE.md) остаётся исследовательским инструментом, а не способом включения функции.
