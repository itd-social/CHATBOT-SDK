# Настройки из окружения и .env

Передайте токен через `ITD_TOKEN` или `ITD_REFRESH_TOKEN`, затем создайте бота:

```python
from itd_bot import Bot, Dispatcher

with Bot.from_env() as bot:
    router = Dispatcher.from_bot(bot, **bot.dispatcher_options)
    router.run_polling(state_path=".bot-state.json", **bot.poll_options)
```

`Bot.from_env()` читает окружение один раз и создаёт обычный `Bot`. `poll_options` и `dispatcher_options` — копии словарей настроек без токенов. Передавайте их явно, как в примере: без этого `poll` и `Dispatcher` используют свои обычные значения по умолчанию. Изменение возвращённой копии не меняет настройки бота. У созданного обычным конструктором `Bot` эти словари пусты.

## Переменные

| Переменная | Значение | Если не задана |
|---|---|---|
| `ITD_TOKEN` | Access-токен без `Bearer` | Нужен refresh-токен |
| `ITD_REFRESH_TOKEN` | Значение refresh-cookie | Нужен access-токен |
| `ITD_SESSION_PATH` | Путь к файлу refresh-сессии; пустая строка отключает сохранение | `.itd-session.json` |
| `ITD_WORKERS` | Целое больше нуля | В `poll_options` не добавляется; обычный `poll` использует 1 |
| `ITD_POLL_INTERVAL` | Конечное число секунд больше нуля | В `poll_options` не добавляется; обычный `poll` использует 2,0 |
| `ITD_READ_MODE` | `blocking`, `background`, `batch` или `off` | В `dispatcher_options` не добавляется; обычный диспетчер использует `blocking` |

Пустые токены считаются отсутствующими. Если нет ни одного, `from_env` поднимет `ValueError` до HTTP-запросов. Оба токена можно передать вместе. Обновление и сохранение сессии работают по [прежним правилам](AUTH.md#хранение-и-ротация).

Явные аргументы `Bot.from_env(...)` имеют приоритет для соответствующего параметра, включая `None`:

```python
bot = Bot.from_env(session_path=None)  # Не сохранять refresh-cookie на диск.
```

Можно передавать и другие существующие аргументы `Bot`, например свой `client` или `limiter`. SDK не печатает значения настроек при ошибке разбора: сообщение содержит только имя переменной и требование к ней. Не выводите токены и файлы сессий в собственные логи.

## Лимиты

Чтобы настроить существующий `RateLimitConfig`, добавьте к имени поля префикс `ITD_RATE_` и запишите его в верхнем регистре:

| Переменные | Формат |
|---|---|
| `ITD_RATE_ENABLED`, `ITD_RATE_WAIT` | `true` или `false`, регистр не важен |
| `ITD_RATE_REQUESTS_PER_MINUTE` | Целое больше нуля или `none` для отключения этого бюджета |
| `ITD_RATE_MIN_INTERVAL`, `ITD_RATE_SEND_INTERVAL`, `ITD_RATE_REACTION_INTERVAL`, `ITD_RATE_EDIT_INTERVAL`, `ITD_RATE_DELETE_FOR_ME_INTERVAL` | Конечные секунды не меньше нуля |
| `ITD_RATE_SEND_BURST`, `ITD_RATE_EDIT_BURST`, `ITD_RATE_REACTION_BURST`, `ITD_RATE_DELETE_FOR_ME_BURST` | Целое больше нуля |

Без переменных `ITD_RATE_*` остаётся прежний общий лимитер для адреса сервера. С указанными полями создаётся отдельный `RateLimiter`, остальные поля берутся из `RateLimitConfig()`. Явный `limiter=` имеет приоритет над всей настройкой лимитов из окружения. Если создаёте несколько клиентов, передавайте им один лимитер для общего бюджета. Разные процессы всё равно не координируются. Значения — защита клиента, не квоты ИТД: [подробнее](RATE_LIMITS.md).

Неизвестные переменные не используются. Ошибки в известных числах, режимах и булевых значениях вызывают `ValueError`; пустые числовые значения тоже считаются ошибкой. Рекомендации для нагрузки — в [бюджете запросов](REQUEST_BUDGET.md).

## Явная загрузка .env

Установите необязательное дополнение:

```sh
python -m pip install "itd-chatbot-sdk[env]"
```

Скопируйте [`.env.example`](../.env.example) в `.env`, заполните один токен и запустите [пример](../examples/bot_env.py):

```sh
python examples/bot_env.py
```

В примере выполняется `load_dotenv(".env", override=False)` до `Bot.from_env()`. Уже установленные переменные окружения имеют приоритет. Это явное действие приложения; импорт SDK и сам `from_env()` файлы `.env` не ищут и не читают. Правила загрузки описаны в [документации python-dotenv](https://bbc2.github.io/python-dotenv/).

`.env` и файлы сессии содержат секреты: храните их вне Git. Стандартные имена уже исключены из Git и архивов; в sdist включён только шаблон `.env.example` без учётных данных. Если используете собственный путь сессии, исключите его отдельно. При работе только с системным окружением дополнение `[env]` не требуется.

Проверено с `MockTransport`, подставными значениями окружения и настоящим `python-dotenv` на временном файле. Живых запросов к ИТД для этой настройки не было.
