# Очереди по чатам

Включите очереди, если один долгий обработчик задерживает сообщения из других чатов:

```python
router.run_polling(
    state_path=".bot-state.json",
    workers=4,
    chat_queues=True,
    chat_queue_size=64,
)
```

События одного чата выполняются по порядку, в том числе между пакетами. Разные чаты используют до `workers` потоков. Опрос продолжает читать следующие пакеты, пока работают обработчики: чат B из следующего пакета не ждёт чат A из предыдущего. При `workers=1` обработчики по-прежнему выполняются по одному. Пример: [`examples/chat_queues.py`](../examples/chat_queues.py).

По умолчанию `chat_queues=False`: сохраняется прежнее ожидание всех обработчиков пакета. Общие данные при параллельной работе защищайте блокировками. Обработчики должны возвращать управление: SDK не может прервать ваш код.

## Когда сохраняется курсор

Для этого режима требуется целый `event_seq` у каждого события: значения должны расти по порядку и не превышать `next_event_seq` пакета. Числа могут идти с промежутками. Поле используется клиентским бандлом сайта. Если его нет или порядок нарушен, SDK поднимет `ProtocolError` до передачи событий этого пакета обработчикам.

Исключение — явный [источник WS](WEBSOCKET_SOURCE.md): его уведомления без номера проходят очередь без продвижения курсора. Они также задерживают подтверждение более поздних событий до завершения своего обработчика.

SDK сохраняет курсор только до первого незавершённого события. Например, события 10 и 30 завершились, а 20 ещё работает: сохранённый курсор не пройдёт дальше 10. После завершения 20 можно сохранить 30. Конечный `next_event_seq` пакета сохраняется, когда завершены все предшествующие ему события.

Обработчик `on_checkpoint` и запись `state_path` выполняются в потоке опроса, а не в потоках обработчиков. Завершение обработчика во время HTTP-запроса будет учтено после возвращения запроса. При ошибке сохранения опрос останавливается.

## Если очередь заполнена

`chat_queue_size` ограничивает число событий одного чата, включая выполняемое. Дополнительно общий буфер незавершённых событий, завершённых событий за пропуском и границ пакетов ограничен `max(2, workers) * chat_queue_size` записями. Один элемент `new_messages` считается одним событием.

Когда достигнут любой предел, SDK ждёт освобождения места и временно прекращает приём следующих событий и запросы `/updates`. Ничего не выбрасывается. При длительной задержке чата A общий буфер тоже заполнится и остановит чтение для B: это ограничение памяти. В памяти также остаётся текущий ответ HTTP; размер одного серверного пакета этот параметр не ограничивает.

## Сбой и повторная доставка

После аварийной остановки часть событий за сохранённым курсором может прийти повторно. `Dispatcher` по умолчанию [подавляет успешно обработанные сообщения](USAGE.md#защита-от-повторной-обработки). Его стандартный кэш живёт в памяти: после перезапуска процесса, вытеснения записи или при ручном использовании `Bot.poll` защиту своих действий от дублей организуйте отдельно.

Временный сбой отметки прочтения в `read_mode="blocking"` останавливает приём новых задач. Уже начатые обработчики завершаются, SDK сохраняет завершённую последовательность и заново читает с этого курсора после паузы. Успешные сообщения внутри повторённого `new_messages` гасятся дедупликацией.

Обычные ошибки обработчиков подчиняются `on_error`: по умолчанию `SKIP` завершает событие как пропущенное, `RETRY` повторяет обработчик, `STOP` останавливает опрос перед неуспешным событием. Частичные внешние действия обработчика не откатываются. При `STOP` или другой фатальной ошибке уже начатый обработчик другого чата ещё может закончить работу, но курсор не перескочит через ошибку. `ResetRequired` выходит вызывающему коду.

`stop` прекращает новые чтения, дорабатывает весь уже полученный пакет и очереди, затем сохраняет курсор. Если обработчик завис, штатная остановка тоже будет ждать его. Паузы после ошибок чтения и WebSocket сохраняют прежние правила. Записи API не получают новых автоматических повторов.

Проверено на `httpx.MockTransport` и подставных сигналах WebSocket. Живое чтение событий в этом режиме не выполнялось.
