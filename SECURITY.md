# Безопасность

Refresh-cookie и файлы сессий дают доступ к аккаунту. Не прикладывайте их к публичным issue, pull request или журналам CI. Если токен попал в публичный доступ, отзовите соответствующую сессию средствами ИТД и создайте новую.

Для сообщения об уязвимости используйте приватное сообщение [автору репозитория](https://itdsocial.com/@itdStatus) или приватное сообщение об уязвимости GitHub, если оно включено в разделе Security. До согласования исправления не раскрывайте подробности публично.

SDK хранит refresh-cookie в локальном JSON-файле открытым текстом, если указан `session_path` или используется путь по умолчанию. Меры защиты и ограничения описаны в [документации по авторизации](docs/AUTH.md#хранение-и-ротация).
